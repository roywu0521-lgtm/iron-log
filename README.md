作業 05：和 AI 討論規格，使用 Vibe Coding 製作互動網頁，再以 GitHub Pages 發布。

本作品已透過 GitHub Pages 發布。

功能包含推拉腿循環課表、動作庫、磅數訓練紀錄、InBody 報告自動辨識、身體與飲食紀錄。

## 檔案

- `SPEC.md`：依需求討論整理的程式規格書。
- `index.html`：完整網站，無需安裝套件；HTML、CSS、JavaScript 都在同一檔案。
- `README.md`：作品介紹、使用方式與作業交付說明。

## 身體與飲食功能

- 訓練重量使用磅（lb）。舊公斤紀錄會自動換算一次，並在同一瀏覽器保留轉換前備份（儲存鍵 `iron-log-v1-before-lb`）。
- 在「身體紀錄」選擇 InBody 照片或 PDF，等待自動辨識，對照原報告確認日期、重量單位、數字後儲存。單檔上限 15 MB，PDF 最多 5 頁。
- 自動辨識需連網載入 Tesseract.js、PDF.js 與中英文模型；運算在瀏覽器執行，原始報告不傳到辨識伺服器。首次載入可能需要一至兩分鐘。
- 不同 InBody 版型、模糊照片、圖表刻度可能無法正確配對欄位；辨識結果必須核對，無法判定的欄位可手動補充。目前以合成報告測試，尚未以使用者的實際 InBody 報告驗證。
- 報告存於 IndexedDB，數據存於 localStorage；可從量測歷程開啟／下載原報告。這些個人資料不在 index.html 內，不會隨 GitHub Pages 網站一起公開。
- 在「飲食紀錄」按日期新增餐點，選填熱量與三大營養素。顯示的是已填數字合計；空白不等於零。

## 先在自己的電腦試用

1. 將 `index.html` 拖入 Chrome 或 Edge。
2. 在「循環，由你開始」指定一個實際的推日，按「更新循環起點」。
3. 點選日期，依自己的課表修改組數與目標次數；選「從動作庫加入動作」補齊內容。
4. 按「開始記錄」，填寫每一組重量與次數，完成後打勾。
5. 重新整理，確認紀錄保留；切換週曆，確認推／拉／腿／休息繼續循環。

資料僅存在目前瀏覽器。檔案直接開啟、localhost 預覽與 GitHub Pages 分別是不同的儲存位置，不會互相同步；請先用測試資料試用，正式紀錄建議在最後發布的網址開始。清除網站資料、使用無痕模式或瀏覽器禁止儲存，可能導致紀錄無法保留；網站會在偵測到儲存錯誤時顯示提示。

當日調整只影響當天，不會讓後續循環自動往後移。已開始的訓練紀錄保存當時課表的副本，日後修改課表不會改寫它。
